### [C-ESPN1] Establish an authenticated ESPN transaction-history contract
- **Severity:** medium
- **Effort:** medium
- **Pickup:** active-agent
- **Ready:** no
- **Files:** `src/fantasy_assistant/espn/`, `src/fantasy_assistant/ingestion/`, `tests/`
- **Status:** OPEN

**Background:** Live authenticated probes of `mTransactions2` accepted waiver/free-agent filters but
returned no transaction list. The league communication endpoint accepted the documented activity
filter shape but returned no topics. Draft and player evidence are available through separate stable
payloads, so transaction behavior must not be inferred from those sources.

**Goal:** Preserve manager adds, drops, waivers, and trades as versioned, evidence-linked events for
behavioral analysis.

**Acceptance criteria:**
- [ ] Identify a live ESPN response that contains at least one known historical transaction without
      printing or committing credentials or private payloads.
- [ ] Add a sanitized offline fixture that pins event identity, timestamp, type, teams, and players.
- [ ] Normalize events with source and fetched-at provenance, tolerating missing optional fields.
- [ ] Store raw responses immutably and expose a CLI sync that handles inaccessible seasons without
      corrupting prior history.
- [ ] Reconcile PRD US-1.4/US-4.2 and the technical design after live validation.

**Proposed approach:** Inspect ESPN's authenticated league activity network calls in an already
signed-in browser, then reproduce the smallest read-only request in the ESPN adapter.

### [C-ESPN2] Resolve historical league identity changes
- **Severity:** medium
- **Effort:** medium
- **Pickup:** active-agent
- **Ready:** no
- **Files:** `src/fantasy_assistant/config.py`, `src/fantasy_assistant/espn/discovery.py`, `tests/`
- **Status:** OPEN

**Background:** The 2026 league status advertises prior seasons back to 2016, and the current league
ID retrieves complete drafts from 2018–2025, but that same ID returns HTTP 404 for 2016–2017. ESPN
likely changed the league/group identity across the historical boundary.

**Goal:** Resolve one logical league to the correct ESPN league ID and user team ID for every
accessible season.

**Acceptance criteria:**
- [ ] Identify the 2016 and 2017 league IDs from authenticated ESPN evidence or document that those
      seasons are no longer accessible.
- [ ] Extend the ignored league profile contract to support season-specific league and team IDs
      without duplicating credentials.
- [ ] Add offline fixtures for a league whose upstream identity changes between seasons.
- [ ] Make historical sync select the correct ID for each season and report inaccessible seasons
      without aborting successful ones.
- [ ] Reconcile discovery/config documentation and live validation evidence.

**Proposed approach:** Inspect the authenticated ESPN fantasy history/profile UI and its network
responses for old group IDs, then normalize those observations into a season-to-identity map.
